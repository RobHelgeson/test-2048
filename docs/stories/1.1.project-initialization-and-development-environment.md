### Project Structure Requirements

[Source: architecture/unified-project-structure.md]
The project must follow Expo's unified structure:

```
test-2048/
├── app/                    # Expo Router file-based routing (REQUIRED)
├── components/             # Reusable UI components (Expo convention)
├── hooks/                  # Custom React hooks (Expo convention)
├── stores/                 # Zustand state stores
├── services/              # Business logic services
├── types/                 # TypeScript type definitions
├── constants/             # Application constants (Expo convention)
├── utils/                 # Utility functions
├── assets/                # Static assets (Expo convention)
├── __tests__/             # Test files
```

Key structure requirements:

- Root-level `/app` directory is mandatory for Expo Router v3
- Root layout required at `app/_layout.tsx` replacing traditional App.tsx
- Components outside `/app` are non-route by Expo convention
- All directories follow Expo template conventions

### TypeScript Configuration Standards

[Source: architecture/coding-standards.md]

- Must extend "expo/tsconfig.base" configuration
- Strict mode must be enabled for maximum type safety
- Never use 'any' type - all interfaces properly typed from /types directory
- Path mapping should support @/ prefix for absolute imports
- TypeScript error checking must be functional during development

### Development Tooling Requirements

[Source: architecture/coding-standards.md#critical-fullstack-rules]

- ESLint with strict rules for React Native and TypeScript
- Prettier for consistent code formatting
- Hot reload and fast refresh must be functional
- VS Code integration for automatic formatting and error detection
- Git conventional commits for consistent version control

### File and Directory Naming Standards

[Source: architecture/coding-standards.md#naming-conventions]

- Components: PascalCase with .tsx extension
- Hooks: camelCase starting with 'use' and .ts extension
- Services: camelCase ending with 'Service' and .ts extension
- Types: camelCase and .ts extension
- Files/Directories: kebab-case for file and folder names
- Test files: Same name as file being tested with .test.tsx/.test.ts

### Testing

[Source: architecture/testing-strategy.md]

**Testing Framework Setup:**

- Jest configured with 'jest-expo' preset for React Native compatibility
- React Native Testing Library for component testing
- Coverage thresholds: 80% for branches, functions, lines, and statements

**Test File Organization:**

```
__tests__/
├── components/            # Component tests
├── hooks/                # Hook tests
├── services/             # Service tests
├── stores/               # Store tests
└── utils/                # Utility tests
```

**Test Configuration Requirements:**

- Jest setup in jest.config.js with expo preset
- Transform ignore patterns for React Native modules
- Setup files for test environment configuration
- Coverage collection from all source directories

**Test Scripts to Add:**

- `test`: Run all tests
- `test:watch`: Run tests in watch mode
- `test:coverage`: Run tests with coverage report
- `test:ci`: Run tests for CI/CD pipeline
